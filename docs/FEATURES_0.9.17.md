# 0.9.17 — profile features and recovery

## Using the new features

- **Edit mode:** Undo and Redo operate on the last 50 geometry, membership or name edits per profile/orientation in this session. A completed drag/resize is one step. Ctrl/Command Z undoes; Ctrl/Command Shift Z or Ctrl Y redoes. Text fields keep their normal undo behavior. Adding tiles, removing tiles, resetting a layout and importing profiles/setups use the same history. Deleted profiles cannot be recovered through this history.
- **Checkpoints:** the first layout change keeps the previous arrangement automatically. Save checkpoint replaces that copy; Restore checkpoint restores it and is itself undoable. Checkpoints are stored inside local settings and survive restart. Surviving tiles keep current config when restoring geometry. A removed tile recovers the config from its snapshot. Shared profile/setup exports exclude checkpoint history.
- **Settings → Data status:** lists active polling sources, setup requirements where known, last successful fetch time, failure/staleness, and manual retry. This covers polling tiles including installed declarative tiles; it is not a health check for every native event stream or account. Source content, credential values and raw errors are not copied into the health registry. A successful fetch can still contain provider-cached data. Hidden windows pause polling.
- **Profile switcher → Automatic profiles and display recall:** disabled by default. Rules match exact process names case-insensitively, accepting Windows names with or without `.exe`; macOS uses bundle identifiers. Four seconds of stable matching are required. Manual selection pauses rules and display recall for 30 minutes; Resume now clears that pause. Editing, overlays and hidden windows suspend decisions. Unmatched apps keep the current profile.
- **Remember this display:** saves the current profile and UI scale. Display recall runs on entry to a different recognized display and app rules can then take over. Missing profiles or unrecognized displays keep the current profile. The key is the OS-provided display name and physical desktop origin, not a hardware serial: after rearranging displays in OS settings, remember them again. Viewport fitting no longer rewrites preferred tile geometry.
- **Onboarding:** now has five steps, including an audio activity meter and optional Discord/Claude tiles. It can be skipped or replayed. Existing profiles are not reseeded. Fresh Work profiles omit those two optional integrations. Location searches discard superseded responses.
- **Shared files:** both profile and setup imports preview geometry and explain required bundles/connections. Setup imports remain additive and honor the 200-tile limit. Install missing bundles through Content library / Market, then configure local accounts in their tiles. Import does not automatically install code or connect accounts. New exports retain names, geometry and a small allowlist of display options (layers, opacity, speed, trail length); personal content, map positions, endpoint URLs, credentials and arbitrary bundle configuration are omitted. Legacy file parsing remains compatible.

## Implementation and validation

Layout history, automation and health have separate state modules rather than embedding their controllers in App. Settings now gate persistence on successful hydration, serialize saves, and surface retryable load/save errors. Empty or non-object native settings files are errors and are not silently replaced with defaults. The existing local file is preserved when loading fails; this release does not attempt automatic repair of corrupted JSON.

Automated checks cover history separation/caps/redo invalidation, durable checkpoint behavior, external settings-import resets, live config preservation, export privacy, dependency status, settings load failures/slow hydration/save ordering/retry, polling failure/source changes/cleanup, and profile automation debounce/manual pause/modal blocking/display scale/cleanup.

The browser automation provider reported no available browser. The native Computer Use service reported an unavailable pipe (OS error 2). No visual desktop, physical audio, or physical multi-monitor smoke test was possible in this session. Hardware behavior still needs field validation; automated tests use deterministic foreground/display inputs. Existing root script tests have an unrelated category mismatch for six `meter` entries in `bundles/metadata.json`, as documented for 0.9.16.

Adaptive automatic FPS/DPR adjustment remains deferred. The review explicitly calls for representative idle/music/gaming/hidden measurements before selecting thresholds; this release retains the existing explicit performance controls.
