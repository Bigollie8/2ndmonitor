# 0.9.20: pacing, webviews, Auto-fit and steady-state audit

Baseline for the integrated change: `215f8c7` (0.9.19); inspected and tested on Windows, 2026-09-19. The initial investigation used an outdated local checkout (`9589348`, 0.9.17). Before pushing, the change was rebased onto current main, preserving the 0.9.18 SessionLog and the 0.9.19 GSMTC crash mitigation. No version bump or installer deployment was performed.

## Evidence and limits

The existing `perfLog.ts` SessionLog and JSON/CSV exports are retained. Its timer runs only while perfDebug is enabled and retains 3,600 samples (two hours at two-second cadence). This change adds optional native process-tree CPU/RAM fields to that same log, using existing sysmon measurements; no parallel log or native sampler is added. Stale CPU/RAM/GPU values become null. Surface registration now responds to the toggle even when the visualizer was already mounted. No historical session export was available for this audit.

[Raw measurements](2026-09-19-gate-measurements.json) were captured through production `recordDraw`/`getSnapshot` and the existing SessionLog using a **deterministic simulated 144 Hz vsync clock**. They measure scheduling and instrumentation, not rendered pixels, CPU, GPU or memory. Reproduce from `app/` with `npx tsx scripts/perf-audit.ts`. The script reads the baseline debug module from pinned commit `215f8c7`, uses a temporary module, and removes it afterward.

No claim of reduced CPU/GPU percentage, eliminated long-term memory growth, or a reproduced Netflix-specific crash is made. There was no controlled native before/after overnight run. The old idlePace comment's resource figures are historical comments, not measurements reproduced here. Browser-dev sysmon generates random mock values and must not be used for hardware claims.

## Remaining measurements and recommendations

- **Idle CPU/GPU — high priority:** draw staging is verified, hardware savings are unmeasured. Capture 5 minutes live, 3 minutes silence, then 5 minutes live with the same layout, visualizer, refresh, performance cap and WebView2 runtime. Compare process-tree CPU/GPU and actual HUD draw rates, not the footer's nominal cap. Expected impact could be large for full-screen shaders; percentage unknown.
- **Pause/resume — high priority:** scheduling tests pass, but subjective smoothness with audio and rendered MilkDrop/scripted bundles remains a manual check. Test ten pause/resume cycles and track gaps. Expected impact is removal of a pending deadline and reduced cadence irregularity; no sustained full-rate throughput increase is claimed.
- **Long-lived memory — high priority:** debug windows and existing session history are bounded. BrowserPlayer deduplicates equal bounds and cleans up observer/listeners. SandboxVizSurface caches dimensions outside its frame pump (`:127–141`), cancels rAF (`:482–483`) and removes its message listener (`:441–442`). MilkDrop clears its preset timer. No continuous React churn or native memory-growth slope was measured. Run Netflix visible for 8–12 hours and separately hidden behind Settings. Export while still running. A future native-memory fix could have high impact, but no leak is established. Do not recycle a playing view on a timer: that would lose playback/session behavior.
- **Long tasks/layout thrash — medium priority:** this harness does not execute browser layout/shaders and provides no real long-task measurement. HUD attribution is heuristic (last draw name), its short HUD window has a 50-record ceiling, while SessionLog uses cumulative counters for accurate interval totals. Observers created before enabling perfDebug are not retroactively wrapped. Reproduce resizing/zooming/overlays with debugging enabled. Coalescing BrowserPlayer's initial/window/RO measurements is a follow-up only if actual counts justify it. Expected impact likely limited to resize interactions; unquantified.
- **Tao panic — high priority:** use the backtrace and preceding lifecycle markers to identify the shutdown caller. Evaluate an upstream fix against a matching stack; speculative dependency upgrades or swallowing the panic are excluded. Expected reliability impact is high if that shutdown path is confirmed.

Microsoft documents ProcessFailed as the notification for WebView2 process crashes/hangs: [process-related events](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/process-related-events). These handlers **cannot guarantee a log for host access violations, abrupt OS termination, catastrophic OOM, power loss or disk-write failure**. For those failures request Windows Reliability Monitor/Application Error details or a dump. Event-registration failure is itself logged.

The upstream [0.9.19 crash investigation](../FEATURES_0.9.19.md) also documents a separate SHCORE fail-fast on a COM worker during GSMTC artwork hand-off and a native EmbeddedBrowserWebView.dll fault without a dump. Its persistent session manager / thumbnail gate mitigation remains intact. Neither that Windows fail-fast nor a host DLL access violation is guaranteed to invoke Rust's hook or a surviving WebView2 callback. This reinforces the request for Windows error details when crash.log has no matching event.

## Auto-fit

`state/layout.ts:317` evaluates regular grids and selects the least squared size change, snaps shared edges, clamps to chrome and enforces 200×140px minimums. A short final row fills the width. Exact minimum-size fits use unsnapped boundaries when snapping prevents a feasible fit. Input order, IDs, types and config references are preserved. `App.tsx:1940` uses the existing updateActiveOrientation/history path. Empty layouts disable the button; impossible fits display a notice without changing the layout. No finite viewport can hold unlimited minimum-size tiles.

Tests cover landscape/portrait/800×600/1080p, exact minimum-size fit, overlaps, chrome bounds, preserved payloads/order, idempotency, empty/impossible inputs and Undo restoration.

## PR description and reporter instructions

This change resets visualizer frame deadlines on playback/visibility transitions, adds undoable Auto-fit, serializes native browser replacement and adds crash diagnostics without destroying the view when Settings or Market opens. It also fixes disabled perf collection and extends the existing bounded session export with native CPU/RAM values.

After the next failure:

1. Open **Settings → Advanced → Crash log → Copy path**. Open the path in Explorer and attach the **actual crash.log file**, not just its pathname. Default: `%APPDATA%\com.secondmonitor.hub\crash.log`. Send promptly because it rotates around 512 KiB.
2. Include app version, failure time/timezone, Windows/WebView2 versions, whether Netflix was playing/paused, duration open and whether Settings/Market or tray-hide was active.
3. For performance reproduction enable **Settings → Advanced → Perf debug HUD**, close Settings, reproduce, then click **Save JSON** in the HUD Session log section and attach `2ndmonitor-perf-<timestamp>.json` (or use **Copy JSON** if downloads fail). Export before exiting/restarting: the ring is in memory and does not survive a crash. It holds two hours at normal two-second cadence; hidden-window throttling can stretch that wall-clock range. Disabling stops collection and clears the log; export before turning it off.
4. If the log has no matching panic/ProcessFailed entry, also send the Windows Reliability Monitor/Application Error entry: faulting app/module, exception code and timestamp.

Validation: frontend suite **1,377 passed**; Rust library suite **198 passed**; production TypeScript/Vite build passed with a bundle-size warning. Native overnight playback and subjective smoothness were not reproduced. No quantified hardware performance benefit is claimed.
